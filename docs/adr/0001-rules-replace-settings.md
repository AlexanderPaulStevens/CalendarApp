# Rules replace settings; closed Scheduling catalog

Planner policy used to split across `AppSettings` knobs and separate condition/action Rules, with Auto blocks only refilled via an explicit rebuild. We decided that all planner configuration lives as parameters on Rule instances in a closed `rule_key` catalog (one instance per key, patch enablement/parameters only); timezone stays in `config.py`. Scheduling Rules continuously reflow their Auto events on every recalculation; editing an Auto event claims it as User; disabled Scheduling Rules drop their Auto events. Non-overlap is a planner invariant, not a Rule. Catalog: `weekly_exercise_goal`, `daily_meals` (including exercise-driven recipe swap on the next Auto meal), `work_schedule`, `study_schedule`, and `batch_shopping` (store-trip Auto events from fridge vs meal needs). Scheduling Rules place Auto events on the calendar directly. `batch_shopping` uses batch/lead-day parameters and places store-trip Auto events only in free time inside store open hours (default 09:00–19:00); work and exercise blocks already occupy the calendar, so non-overlap keeps trips out of those windows.
